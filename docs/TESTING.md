# 검증 및 출시 점검

## 자동 검증

Node.js 24에서 `npm ci && npm run verify`를 실행한다. 콘텐츠 검증, Svelte/TypeScript 검사, 단위·도메인 통합 테스트, 정적 프로덕션 빌드를 포함한다. CI도 같은 명령을 사용한다.

서비스 워커 테스트는 캐시·네트워크 모형에서 실제 워커 코드를 실행한다. 실제 브라우저의 설치 권한, 스토리지 정책, 모바일 터치 동작을 대신 검증하지 않는다.

## 브라우저 출시 점검

`npm run build && npm run preview` 후 다음 시나리오를 확인한다.

1. 처음 실행해 Python 변수 레슨을 시작한다. 자료구조 레슨은 선행 학습 전 잠겨 있어야 한다.
2. 첫 답을 틀리면 정답은 공개되지 않고 재시도가 필요하다. 두 번째 제출 후 설명과 정답이 나타난다.
3. 저장이 완료된 뒤에만 계속 버튼이 활성화된다. 저장소 오류가 있으면 동일 답안의 저장을 재시도한다.
4. 레슨 도중 나갔다 돌아오고 새로고침해도 저장된 단계부터 이어진다. 이미 저장한 문제는 중복 기록하지 않는다.
5. 레슨 완료 후 다음 레슨이 열리고, 진행도·경험치가 반영된다. 첫 시도에서 틀린 문제는 Again으로 예약된다.
6. 복습 시간이 지난 뒤 복습 화면에서 동일 문제를 다시 푼다. 이후 첫 시도 정답은 Good으로 예약된다.
7. 설정에서 백업을 다운로드하고 초기화한 뒤 복원한다. 파일명과 복원 확인란에 백업 생성 시각이 표시되고, 첫 문제 전까지 진행한 레슨을 포함해 기록과 복습 일정이 돌아오는지 확인한다. 잘못된 JSON의 복원은 기존 기록을 보존해야 한다.
8. ‘오프라인 학습 준비 완료’ 표시 후 네트워크를 끊고 새로고침한다. 아직 방문하지 않은 레슨도 열려야 한다.
9. 새 배포가 있으면 현재 문제가 유지되고, 사용자가 업데이트 버튼을 누른 뒤 새 버전으로 전환되어야 한다.
10. 모바일 폭, 키보드만 사용, 화면 확대 200%에서 문제 선택·순서 이동·연결·뒤로가기를 확인한다.
11. 학습 경로에 처음 들어가면 현재 열린 Python·컴퓨터 구조·이산수학 트랙만 보이고 첫 트랙이 기본 선택되며 스와이프 안내가 표시되어야 한다. 안내를 닫은 뒤 새로고침해도 다시 나타나지 않아야 하며, 좌우 스와이프와 이전·다음 버튼·트랙 탭으로 열린 트랙 사이를 이동할 수 있어야 한다. 다음 패널은 이동 방향에 맞춰 옆에서 미끄러져 들어와야 하며, 동작 줄이기 설정에서는 즉시 전환되어야 한다. 잠긴 트랙은 화면이나 탐색 대상에 나타나지 않아야 한다.
12. GitHub Pages 배포본의 하단에는 `배포 기준 <짧은 커밋 SHA>` 링크가 표시되어야 하며, 링크는 해당 GitHub 커밋으로 이동해야 한다. 로컬 개발 빌드에서는 `로컬 빌드`가 표시되어야 한다.

## 네이티브 빌드

`npm run mobile:sync`는 웹 빌드와 Android/iOS 소스 동기화까지 수행한다. 서명된 APK/AAB/IPA 생성은 별도다.

- Android: Capacitor 8이 요구하는 JDK, Android SDK 및 Android Studio에서 `npm run mobile:android`로 연다.
- iOS: macOS와 Xcode에서 `npm run mobile:ios`로 열고 개발 팀/서명을 설정한다.
- 실기기에서는 백그라운드 복귀, 시스템 뒤로가기, 키보드, 파일 선택·백업 다운로드 및 오프라인 재실행을 확인한다.

현재 작업 환경에는 Android SDK와 Xcode가 없어 네이티브 실행 파일 빌드 및 서명·실기기 테스트를 수행하지 않았다.
